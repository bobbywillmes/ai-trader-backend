# Phase 9A realtime provider shadow comparison

Phase 9A gives live/direct market data a provider-neutral contract and a Massive-backed production entrypoint. It does not activate Tiingo for Momentum, charts, dashboard, admin estimates, runtime sizing, risk health, or trading. See [the frozen callsite audit](../architecture/massive-runtime-dependency-audit.md).

Tiingo's consolidated realtime endpoint is a beta reference-price feed from multiple venues. Tiingo recommends its IEX endpoint for production realtime use, but IEX last-sale and quote fields may be null without exchange entitlement. The IEX comparison uses the documented `tngoLast` reference price and preserves nulls. Neither endpoint is selected as authority. There is no WebSocket in this phase.

The manual command is `npm.cmd run market-data:realtime:compare -- --symbols=SPY,RSP,AAPL,MSFT`. It makes bounded, concurrent REST requests for each explicit symbol: Massive snapshot plus adjusted extended-hours one-minute aggregates, Tiingo consolidated snapshot, Tiingo consolidated historical one-minute bars with `afterHours=true`, `forceFill=false`, and explicit OHLCV columns, and Tiingo IEX snapshot. It writes token-free `detail.json` and compact `summary.json` under a timestamped ignored `.cache/realtime-market-data/` directory. It does not read or write the database, select a provider, or scan the full security universe. Run it during representative regular and extended market conditions and retain the artifacts for review.

The first live capture showed Massive about 15 minutes behind Tiingo. Current Tiingo consolidated versus IEX reference prices are compared directly. Current Tiingo versus delayed Massive is labeled `UNALIGNED_SNAPSHOT_DIFFERENCE`, with both timestamps and their age delta; it is not an accuracy measure. The Massive snapshot is compared to the Tiingo one-minute close at the **exact minute containing Massive `observedAt`**. If that minute is absent, alignment is unavailable; no current or nearest-prior price is substituted.

Minute statistics use the current New York session only and then the intersection of the two providers' first/last timestamps. This removes prior-session bars that can appear in Massive's rolling lookback. Tiingo's newer tail is outside this overlap, not a Massive coverage gap. Detailed artifacts retain aligned differences and provider-only minute timestamps. The summary includes per-symbol median, p95 and maximum absolute and basis-point close differences, volume differences/ratios, and cross-symbol distributions. Coverage and provider-only counts use New York `OVERNIGHT` (20:00–04:00), `PREMARKET` (04:00–09:30), `REGULAR` (09:30–16:00), and `POSTMARKET` (16:00–20:00) buckets. These are clock segments, not exchange-calendar eligibility claims.

The command records start, completion and provider fetch times. Freshness uses the provider fetch time; a future provider timestamp is shown as zero age with separate `clockSkewMs`. Previous close, day high, day low and day volume are compared pairwise with explicit nulls and `semanticEquivalence=UNVERIFIED`. Volume diagnostics include each provider's minute-volume sum through the Massive cutoff versus its snapshot day volume, plus both sums on the exact shared timestamps. No scaling is applied.

Massive's session VWAP is reported. Tiingo consolidated REST has no documented equivalent session VWAP. The `EXPLORATORY_MINUTE_TYPICAL_PRICE_VWAP` is `(high+low+close)/3` weighted by Tiingo minute volume only through the Massive cutoff, with regular-only and extended-inclusive views. Its comparison with Massive is diagnostic because session and provider volume semantics may differ. It never enters Momentum scoring. Momentum's scoring version, freshness rule, VWAP gate, candidate transitions and handoff remain unchanged.

Massive daily chart/admin candles request `adjusted=true`; the Phase 8 raw canonical daily panel is not an arbitrary-symbol chart substitute. Trading-critical latest-price consumers still fail closed on missing positive Massive prices. No provider fallback exists.

## Relative-volume parity extension

The shadow command also reports provider-internal volume intensity at the common delayed minute cutoff. For each provider it sums current New York session one-minute volume through that cutoff and divides exact 5-, 15-, or 30-minute recent-window volume by **that provider's own** cumulative sum. The 30-minute window is the primary V6-default comparison; the 5- and 15-minute windows are diagnostics. The artifact records the configured `MOMENTUM_CONFIRMATION_RECENT_WINDOW_MINUTES`; if it differs from 30, the primary comparison is labeled as not matching the configured window.

Each recent window requires every expected minute with finite nonnegative volume. A provider's intensity is unavailable if its window is incomplete, cumulative volume is zero, or either provider lacks volume at a timestamp observed by the other anywhere in the cumulative interval. Partial observed sums are labeled separately; complete recent and cumulative volumes are null when required evidence is missing. Both providers could omit the same minute without detection, so `COMPLETE_ON_OBSERVED_UNION` is a stated evidence limit, not a guarantee that every possible trade minute existed. Missing rows and null volume are never counted as zero. The command does not reconstruct trades or rescale volumes.

For an available 30-minute intensity, the shadow bucket mirrors V6's fixed thresholds: `STRONG` at 10% (20 intensity points), `MODERATE` at 3% (10 points), otherwise `LOW` (zero intensity points). No production scorer is called. Dollar-liquidity estimates use each provider's **exact common-cutoff minute close** multiplied by its cumulative volume, with the configured dollar-volume minimum. The buckets mirror V6's strict hard block below 20% of minimum, below-half, moderate (at least half), and minimum-met boundaries. These estimates are separate from relative intensity and do not affect a candidate.

Cumulative checkpoints are reported at reached 10:00–15:00 ET hours and the common cutoff, with Tiingo/Massive ratios only when both providers cover the observed-minute union through the checkpoint. `summary.json` adds per-symbol windows and decisions, cross-symbol intensity distributions, bucket/point/liquidity agreement counts and rates, and checkpoint-ratio distributions. It does not rank or select a provider.

Any trading-critical authority change needs a separate acceptance and rollout contract.
